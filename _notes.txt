Updating

because the service worker caches files, edits to the package do not show up on right away.
Whenever you change anything, bump CACHE to random-draw-v2, v3, and so on.
That forces a refresh, and the activate handler cleans up the old cache.

Real images: list image files in FILES in sw.js so they are available offline.

Relative paths: keep paths relative ("sw.js", "./", never "/sw.js"). The site lives under /random-draw/, and absolute paths would break it.

### test locally before committing

1. open terminal in the folder with all files (index.html etc)
2. start the server with     python3 -m http.server 8000 (or py -m http.server 8000)

3. open http://localhost:8000 in browser
4. stop the server with Ctrl+C when done

Reload with Ctrl+Shift+R after each edit, so you get your new files and not a cached copy.
Press F12 and open the Console tab. Red errors there (a typo in items.js, a missing image) show up immediately, before anything is pushed.
Under Network, a 404 on a photo means the path in your list doesn’t match the file name. Remember that GitHub Pages is case-sensitive, so Photo1.jpg and photo1.jpg are different files. Under Application > Service Workers you can see whether sw.js registered, and Application > Manifest shows whether the app counts as installable.

Things to know

Anything you save in the in-app menu is stored per origin. localhost:8000 and your github.io site keep separate saved lists, so a clean localhost test shows exactly what items.js contains. To reset it, run localStorage.clear() in the Console and reload.
The service worker you register on localhost:8000 can keep serving old files in that browser. If a change doesn’t appear even after a hard reload, tick “Update on reload” under Application > Service Workers, or use “Unregister” there.
You can reach the server from your phone too, if it’s on the same Wi-Fi: open http://<your-laptop-IP>:8000. The page will load and run, but the service worker and the install option won’t work, since that address isn’t localhost or https. That makes it good for checking layout on the real screen, but not for testing the PWA part.
